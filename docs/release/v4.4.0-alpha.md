# Iron v4.4.0-alpha: Strings, Closures and Shared Lists

Every value Iron programs create is now freed by its owner, and lists can be shared. This is an **alpha** release; the surface may change before GA.

## Strings are freed

A heap string's characters now sit behind an atomic reference count. Every owner of a copy of the value (a binding, a field, a list element, a closure or spawn capture) keeps the characters alive, and the last one frees them: bindings at scope exit, fields and elements with their object or list, temporaries after the call or interpolation that used them. Inline strings and interned literals are never counted, so short strings and literals cost nothing. Before this release every long or built string leaked.

- **API change:** `s.release()` on a string, and the `HttpRequest.release`, `HttpResponse.release`, `WebSocketMessage.release`, `FileReadResult.release` and other `*Result.release` helpers now do nothing. They are kept so existing code compiles; releasing by hand would free a string twice.

## Closures own their environment

A capturing closure's environment is reference counted too. Copying a closure, returning it from a function, storing it in a field or a list, or capturing it in another closure keeps the environment alive, and it is freed with the last copy. Before, a closure that outlived the binding it was created in read freed memory, and a returned or stored closure leaked its environment.

## Shared lists and closure captures

- **`rc [T]`** is a shared, counted list. Every copy of the handle (a binding, a parameter, an object field, a closure or spawn capture) reaches the same list, it can be grown through any handle, and the list is freed with the last handle.
- **Closures borrow lists only for a call.** A lambda passed directly as an argument may read a list; a closure that is bound, returned or stored cannot capture a list (E0328), because it would outlive the list's owner, and a `spawn` that captures a list must be awaited in the same block. Share the list as `rc [T]` instead.

## Lists

- `map`, `filter`, `reduce` and `forEach` work on lists of any element type, and `map` produces a list of the lambda's return type (`[String]` to `[Int]`, `[Int]` to `[String]` or `[Bool]`). They used to compile only for numeric lists, and only to the same type.
- `[func]` lists copy and free their elements' environments.

## Fixes

- A `String?` or `Int?` field in an object did not compile, and a constructor argument for such a field left it null.
- Calling a closure value passed its arguments through a variadic pointer, which on Apple arm64 gave the lambda garbage arguments.
- A `func` typed field can be called through its object: `h.run(4)`, with the field's signature.
