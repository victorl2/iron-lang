# Iron v4.7.0-alpha: Windows, Cross Compilation and an SDK-Free Runtime

Windows is a first-class host, every release ships its own pinned C toolchain and a precompiled runtime, and `--target` builds Linux, macOS and Windows programs from any of them. Enums, closures, spawns and fixed-size arrays now own what they hold. This is an **alpha** release; the surface may change before GA.

## Windows

- **Release archive and installer.** `iron-4.7.0-alpha-windows-x86_64.zip` and `irm https://ironlang.dev/install.ps1 | iex` (the installer was published with v4.6.0-alpha but no Windows archive was, so it failed with a 404).
- **No Visual Studio needed.** The archive ships the precompiled runtime for `windows-x86_64`: programs link with `lld-link` against the Universal C Runtime and the other DLLs of Windows 10 and later, with Iron's own entry point instead of the MSVC startup code, so neither the Build Tools nor the Visual C++ redistributable is required. raylib programs and HTTPS work the same way.
- The compiler, `ironls` (including `--supervised`), `iron test`, the web target and the Zed extension's `ironls` download all work on Windows.
- Fixes found by running the whole suite on Windows: `Iron_io_copy_file` and `Iron_io_move_file` treated every existing file on the same drive as the source (`stat()` reports `st_ino` 0 there), so overwriting failed; native builds compiled without `-fwrapv`, so `Int` overflow was undefined behaviour; panic locations lost the backslashes of the path; raylib programs did not link natively.

## Cross compilation

- `iron build --target=<os>-<arch>` with `linux-x86_64`, `linux-arm64`, `macos-arm64`, `macos-x86_64` and `windows-x86_64`, from any host and without an SDK. The program is linked against a **runtime bundle** for the target (`iron-rt-<version>-<target>.tar.gz`, downloaded and verified on first use): a static musl executable for Linux, a program linked against `libSystem.tbd` stubs for macOS, and the UCRT through generated import libraries for Windows.
- Every bundle carries **TLS**: OpenSSL 3.5, built statically, linked into programs that import `http` or `websocket`. The Windows and macOS bundles also carry **raylib**. A Linux cross build of a raylib program is refused, because a static executable cannot load the system's OpenGL.
- On Windows and macOS a native build uses an installed bundle too, so the Build Tools and the Xcode command line tools are needed only to build without one.

## Toolchain

- `ironc` compiles with its own pinned LLVM 23.1.2 (clang and lld) on every host and never uses a compiler from `PATH`; `iron toolchain info | path | install | check` expose it. The generated C is freestanding: it includes only the runtime header and clang's own headers.
- When a platform prerequisite is missing, `ironc` names it and offers to run the installer.
- Concurrent first-use installs of the toolchain or a bundle no longer clobber each other (parallel builds on a fresh machine all failed before).

## TLS

- Servers are verified against the system's trust: the distribution's or macOS's CA bundle (`SSL_CERT_FILE` and `SSL_CERT_DIR` still override it), and on Windows the chain is checked by CryptoAPI, which also fetches roots Windows has not stored yet.

## Language and runtime

- Enums own their payloads; payload enums work as object fields and list elements; a payload declared as an interface accepts its implementors.
- Closures and spawns own their copies of captured `val` objects, interfaces, vectors, optionals and enums; a recursive lambda stored in the `var` it captures is freed.
- Fixed-size arrays `[T; N]` are inline values: copies no longer alias, and the buffer and its elements are freed. They gain `map`, `filter`, `reduce`, `forEach`, `sum` and slicing.
- Nullable objects (`T?`) are destroyed, and `T?` fields of user types compile.
- Type arguments are inferred through generic instances (`swap(p)` with `p: Pair[Int]`).
- Interpolating an object or an enum compiles; unknown methods on `String`, `Int`, `Int32` and `Float` are E0220.
- The runtime catches a double free by address before reading the freed header.

## Tooling

- `iron fmt` indents with four spaces by default, matching everything else.
- The unit and LSP test suites build and run on Windows, and CI builds them there.
