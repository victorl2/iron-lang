# Iron v4.0.0-alpha — Memory Model Overhaul

> Tagged from `main` at SHA `<FILL: short-sha post-tag>`. Acceptance corpus pass-rate at milestone close: see [Acceptance corpus pass-rate](#acceptance-corpus-pass-rate) below (measured on silvaserver, `iron-lsp-build:latest` 8 GB podman). Full reproducer in `docs/dev/PHASE-36-CLOSEOUT.md`.

Iron v4 is a ground-up rework of the language's memory model. The compiler now distinguishes binding tiers (`val` / `var`), parameter modifiers, reference-counted lifetimes (`rc` / `weak rc`), arena allocation, checked pointer types (`*T` / `*var T`), and resource discipline (`drop` / `copy` / `nocopy`) at the type level. The LSP, the three editor extensions, and the stdlib have been adapted to the new surface. This is an **alpha** release; the surface may change before GA.

## What's new

The §12 memory-model overhaul shipped in 17 sequential phases (17–33), followed by LSP adaptation (34) and grammar + editor + corpus catch-up (35). Each entry below is one sentence describing the feature; design closeout docs under `docs/dev/` carry the full story.

### Binding discipline (Phases 17–18)

- **val/var tier discipline (Phase 17)** — `val` is the default immutable binding; `var` opts into mutation at the binding site. Fields, locals, and parameters all participate.
- **Parameter modifiers (Phase 18)** — function and method parameters carry an explicit mutation tier; a `var` parameter signals the caller that the binding will be re-bound or the underlying memory mutated.

### Pointers and policies (Phases 19–21, 25–28)

- **Generational pointers (Phase 19)** — every heap allocation carries a generation counter; use-after-free is caught at every dereference. Foundation for everything below.
- **Checked pointer types `*T` / `*var T` (Phase 20)** — pointer mutability is part of the type. `*T` is a read-only checked pointer; `*var T` permits writes through the pointer.
- **`heap` policy + `free` (Phase 21)** — explicit `heap` allocation policy returns a fat pointer; the matched `free` releases it and invalidates outstanding pointers (caught at next dereference via the Phase 19 generation guard).
- **`*unchecked T` + `Box[T]` (Phase 25)** — escape hatch for FFI and zero-overhead interop. `*unchecked T` skips the generation check; `Box[T]` is a checked single-owner heap box.
- **`rc` policy (Phase 26)** — reference-counted shared ownership. Atomic refcount with a 24 B header (`refcount` + `drop_fn` + `weak_count`).
- **`weak rc` policy (Phase 27)** — non-owning observer of an `rc T`; `upgrade()` returns `T?` and is race-free against concurrent drops (Rust `Arc::Weak` discipline).
- **Arena allocation (Phase 28)** — explicit arena-scoped allocations release at arena exit; `rc` and `weak rc` are excluded from arenas (incompatible lifetime models).

### Purity and resources (Phases 22, 24)

- **`readonly` purity tightening (Phase 22)** — `readonly` methods structurally prevent mutation, including through transitively-readonly captures. `pure` is a strict subset of `readonly`.
- **Resource types `drop` / `copy` / `nocopy` (Phase 24)** — object declarations opt into resource discipline. `drop` blocks run at scope exit; `copy` declares deep-copy semantics; `nocopy` forbids implicit duplication.

### Storage shapes (Phase 23)

- **Bounded vector `[T; <=N]` (Phase 23)** — fixed-capacity stack-allocated vector; bounds checked at push.

### Optimizations (Phases 29–30)

- **Atomic refcount elision (Phase 29)** — local non-escaping `rc` allocations bypass atomic increments; verified via Phase 29 microbench.
- **Pointer-check elision (Phase 30)** — 4-tier escape analysis removes redundant generation checks when the compiler can prove no `free` is reachable between checks.

### Diagnostics and tools (Phases 31–32)

- **Debug allocator + leak detection (Phase 31)** — `ironc build --debug-build` instruments every allocation with origin + leak-at-exit reporting (the debug allocator rides the debug-build flag; there is no separate `--debug-allocator` flag).
- **`defer` statement (Phase 32)** — LIFO scope-exit hook. Pairs naturally with `heap` / `free` and resource types.

### Stdlib and ecosystem (Phases 33–35)

- **Stdlib container rewrite (Phase 33)** — new container surface: `Mutex[T]`, `RWLock[T]`, `Channel[T]` (bounded), `FileHandle` — all `nocopy` types with `drop`-on-scope-exit semantics. Resolved OQ-01 + OQ-06 (closure-capture vs container-drop ordering).
- **LSP adaptation (Phase 34)** — hover annotates the memory-model regime + readonly/pure status; completion gates v4-only keywords by context; 5 quickfixes for the new 800-range error codes (add `val`, insert `defer free`, drop `var` modifier, use `weak rc`, remove `readonly` + extract mutating block). HARD-24 parity gate stayed green throughout.
- **Grammar + editor extensions + corpus migration (Phase 35)** — tree-sitter and TextMate grammars cover every v4 construct; the three editor extensions (VSCode, Neovim, Zed) all pin `compatible_ironls = ">= 4.0.0, < 5.0.0"`; 225 of 388 v3-archive fixtures hand-migrated to `tests/integration/v4/migrated-from-v3/`, the remaining 163 documented as internal-IR / optimizer-internal / removed.

## Migration

The v3 → v4 syntax delta is mechanical for most user code but structural for code that relies on implicit mutation or unbounded references. The [migration guide](../site/migration-v3-to-v4.md) walks through every change with before/after code blocks.

There is **no automatic codemod** for this milestone (deliberate roadmap decision). Hand-migration with the LSP's 5 new quickfixes is the supported path.

## Acceptance corpus pass-rate

**227 / 255 PASS** (silvaserver `iron-lsp-build:latest` 8 GB podman, `ctest -L v4-acceptance` aggregating the `test_v4_acceptance` harness: `PASS=227 FAIL=28 XFAIL=115 TOTAL=370` — the headline denominator excludes the 115 XFAIL fixtures and counts strictly `PASS / (PASS + FAIL)`). See `docs/dev/PHASE-36-CLOSEOUT.md` for the full silvaserver reproducer.

Phase 35 baseline (pre-Phase-36): **228 / 255 PASS** with the same denominator semantics. Phase 36 measurement shows a one-PASS regression to **227 / 255**; the delta is one fixture that flipped from PASS to FAIL between Phase 35 closeout and the Phase 36 release-artifact build.

Pre-merge review update (PR #69): **`PASS=242 FAIL=0 XFAIL=126 TOTAL=370`** — the full
suite is 412/412 green in Debug and Release, in a 6 GB container.

The "28 carried-forward failures" were masking real defects. The `rc`/`weak rc`/
pointer-elision fixtures could never compile — they used `Type(field: value)`
named-argument construction, which `docs/language_definition.md` explicitly lists
as a COMPILE ERROR ("Positional arguments only") — so they never reached the
compiler's back end and never tested anything. What they hid:

- **A release-build shipping-blocker.** `TypeCtx` was not zero-initialized, so
  the uninitialized `in_arena_block_depth` read nonzero under optimized builds and
  every `rc`/`weak rc` allocation falsely failed with E0301 ("rc cannot be
  allocated in an arena"). The memory model's centerpiece could not compile in a
  Release build. Fixed (`TypeCtx ctx = {0}`).
- **Method calls on an `rc` value did not work at all.** Neither the typechecker
  nor HIR→LIR unwrapped `rc T` when resolving a method call, so `rc_val.method()`
  emitted a call to a nonexistent `Iron_unknown_<method>` and lost the result type.
- **`weak rc T` as a method parameter segfaulted the compiler** (a NULL `name` on
  the annotation wrapper reached `strcmp` in `hir_lower`).
- **Interface dispatch to any mutating impl could not compile** — the thunk passed
  the receiver by value where a pointer receiver was expected.
- **A parser infinite loop** that exhausted memory on ordinary malformed input
  (`object A { return 1 }`), which is what OOM-killed `test_typecheck` and, on CI,
  the runner agent itself — surfacing as "The runner has received a shutdown
  signal" / exit 143 and reading like infrastructure flakiness.

The 27 fixtures now use spec-legal positional construction and genuinely build,
run and match. Fixtures resting on surfaces that do not exist keep an honest
`@expected-pass-after` marker naming the missing surface.

## Known limitations / residuals

These items are deliberately deferred or are pre-existing environmental issues. They do not block v4.0.0-alpha.

Carried forward from Phase 34 closeout (items struck through were fixed in
the pre-merge review pass — see the PR #69 review):

- TSan-instrumented runtime tests skip in CI (`libtsan` unavailable in the build container — CI infra issue, not a runtime defect).
- ~~`WILL_FAIL` polarity inversion across the positive corpus~~ — fixed. The
  per-phase `ironc build` rows used `WILL_FAIL` to encode "the check-only
  container has no clang". That is an inversion, not a skip: on a clang-equipped
  host a row went red the moment its fixture actually built and ran, and while a
  fixture was broken the row sat green — which is how a corpus that could not
  compile its own centerpiece still looked healthy. Those rows are now gated on
  `find_program(clang)` (`DISABLED` where clang is absent, a real assertion where
  it is present), and rows for genuinely-unimplemented fixtures derive `WILL_FAIL`
  from the fixture's own `@expected-pass-after` marker via `iron_fixture_xfail()`
  — the same rule `tests/run_tests.sh` applies to the aggregate row. Both
  harnesses now read one source of truth, which is what let them drift apart.
  (`defer_break_continue.iron` referenced `break`/`continue`, which are not Iron
  keywords; replaced by `defer_loop_iteration.iron`.)
- ~~Four missing `.expected` files in `tests/integration/v4-fail/7.5-stdlib/`~~ — fixed: added the E0286/E0206 substring files; negative corpus is now 51/51.
- ~~`test_parser_recursion_guard` stack-ulimit dependency~~ — fixed: the
  crash was a post-trip amplifier (the iterative Pratt climb wrapped the
  error node once per leftover token during recovery, and the guard-less
  analyzer overflowed on the resulting input-length-deep AST). The climb
  now stops on error nodes during recovery; the depth ceiling stays 1000.
- `benchmark_smoke` timeout on slower CI runners.
- ~~`readonly-method-return-Result` fixture violations~~ — fixed: E0280 now
  accepts enums (ADTs) whose variant payloads are readonly-compatible, which
  also unblocks `Result[Void, E]` returns and structs with enum fields
  (raylib `Camera3D`, `KeyboardKey`, …).

Deferred-release leaks (POL-09 / OQ-03):

- A successful `weak.upgrade()` takes a +1 strong reference, but scope exit
  does not yet release an `rc T?` binding (the conditional release needs
  optional-payload access at the LIR layer). The upgraded object therefore
  outlives its last owner — a leak, not a safety hole. Surfaced when the
  `4.9-weak-rc-policy` / `4.10-rc-elision/weak_upgrade_pair` fixtures are
  built. The closure env teardown has the sibling gap: `env_drop` does not
  release captured rc values (`4.8-rc-policy/closure_captures_rc`).
- Arena allocation is broken in codegen: `emit_c` passes `Iron_Arena` where
  `Iron_Arena_RT *` is expected, so the `3.7-arena` / `8.6-composition-arena`
  fixtures do not compile (identical in Debug and Release). `Box.takes_
  ownership` builds but does not run the moved value's `drop`. Both were only
  reachable once the corpus was brought to the real surface; they are latent
  behind the shipped fixtures' parse errors.

Platform: arm64 user-method-call codegen loop (pre-existing):

- On arm64 (Apple Silicon Linux containers), `ironc build` enters an
  unbounded-memory loop during HIR→LIR lowering of any user-defined method
  call (`obj.method()`), independent of optimization level and build type;
  `ironc check` (analysis only) is unaffected, and x86_64 (CI + silvaserver)
  is unaffected — which is why the corpus builds and the 227/255 metric hold
  there. This blocks local build+run verification of method-using fixtures on
  arm64 but does not affect shipped x86_64 artifacts. Flagged as a follow-up;
  the bisect points at method-call lowering (field access and builtin-method
  calls like `.upgrade()` are fine).

Concurrency-container destructor gap (STDLIB-07/08):

- Dropping a non-empty `Channel[T]` reclaims the queued items' box memory
  (fixed in this release) but does NOT run `drop` for resource-typed queued
  elements; dropping `Mutex[T]` / `RWLock[T]` frees the value slot without
  running `T`'s `drop`. Avoid parking resource types (e.g. `FileHandle`)
  in concurrency containers at drop time until a follow-up wires
  element-drop glue through their destroy paths.

Compiler / LSP residuals from Phase 34 closeout:

- Additional 800-range diagnostic code allocations are pending (`memory_model_hint` consolidation).
- LSP-10 "Extract mutating block" quickfix ships as a placeholder; full implementation deferred.

Alpha-stage caveats:

- The surface may change before GA. Pin your editor extension to `>= 4.0.0, < 5.0.0` (the default range in all three extensions) but expect minor surface refinements in beta and RC.
- The 168 requirements are CLOSED on the project tracker; that does not mean every edge case across them is exhaustively tested. The alpha period is when external users surface the remaining edge cases.
