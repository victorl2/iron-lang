# Iron v4.10.0-alpha: Correctness and Spec Coverage

A correctness release found by testing every rule, form, error code and library call the manual lists. Programs that walk linked lists with null checks compile, several memory bugs are fixed (a pattern binding freeing its list, a leaked `upgrade()`, a narrowed variable read through a pointer), and the test suite now measures how much of the manual it exercises: 582 of 583 units. This is an **alpha** release; the surface may change before GA.

## Language

- **For loops walk iterables.** `for x in xs` iterates a list, a String, a Map or Set, or `range(n)`. `for i in 10` is an error (write `range(10)`), as is a loop over any other value; `range(n)` is written only as a loop's iterable.
- **Narrowing through assignment.** `x != null` narrowing survives assignments of non-null values, so `while cur != null { total += cur.value; cur = cur.next }` walks a linked list, and `while` narrows its body. A binding assigned in a loop body or a closure is not narrowed there by an outer check.
- **Mutating calls follow the field rules.** A method that writes self, called on a list element or through a field of a `val`, is E0235; through a `val` rc handle it is allowed, as a field write already was.
- A list of tuples is an error (tuples return several values and are taken apart at once), and so is `[T; N]` used as a value outside `heap`. A method named `drop` is E0237: the destructor is `drop { ... }`.

## Fixes

- A pattern binding of a list, map or set payload (`Bag.Items(xs) -> ...`) freed the payload, so a second match or the value's own drop crashed. It now borrows the payload.
- `w.upgrade() != null` leaked the upgraded reference, so the object was never dropped.
- A `var` whose address is taken could be narrowed to a smaller integer and read through the pointer as an Int.
- A `T` argument to a `T?` parameter of a method, an init or an interface method failed in the C compiler.
- These failed to compile:
  - enums whose payload is a list of an enum or a Map;
  - lists of pointers;
  - `n += 1` on a narrowed `Int?`;
  - `rc T?` slots assigned in a branch.
- A static call to a method a type does not declare, a method call on a call returning nothing, and a program without `main` are reported by the compiler instead of failing later.
- `ironc check --target web` runs the web-only checks (E0501 for `await`).

## Diagnostics

Errors say what to write instead for:

- `1e20`, `t.0`, `0..n`, `a ** b`;
- `val s = match ...`, a missing `:` in a binding;
- a keyword used as a name, a method in an enum body;
- `Int("42")`.

Missing fields and methods name the type and suggest the closest one, and calling a non-readonly method that never changes self suggests `readonly`. A missing `init` is written out. Comparing a value that is never null with `null` warns (W0616). One mistake no longer produces a cascade of errors.

## Tooling

- `scripts/spec_coverage.py` measures the manual's grammar alternatives, error codes, library calls and examples covered by tests (582 of 583), and a ctest keeps covered units covered. The standard library parses with the manual's grammar.
- Hover shows the doc comments of methods declared inside objects and patches.
- The manual documents that string positions clamp and that `to_int` accepts surrounding whitespace.
