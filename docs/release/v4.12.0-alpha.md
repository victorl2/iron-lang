# Iron v4.12.0-alpha: Debugging in Iron Terms

What you type and see while debugging is Iron now: hover, watch and the debug console take Iron expressions, breakpoints take Iron conditions and log messages, Step Into stays in Iron code, and every editor can run or debug a file or a single test block. This is an **alpha** release; the surface may change before GA.

## Debugging

- **Iron expressions** in hover, the watch view and the debug console: `xs.len() > 2 and not done`, `name == "ann"`, `ages.get("ann")`, `xs[i] * 2`. Before, these went to the debugger as C and failed (or, for string `==`, compared pointers).
- **Breakpoints in Iron**: conditions (`i == 7 and total > 20`), hit counts (`5`, `>= 5`, `% 5`) and logpoints whose `{expr}` parts are filled in like an Iron string.
- **Step Into stays in Iron code**: it enters `square(4)` and steps over the runtime behind `println(...)` or `xs.push(v)`, instead of walking through the runtime's C.
- **Debug one test**: `"test": "<name>"` in a launch configuration builds the file with `--test` and runs only that test block, so its breakpoints stop.
- **What the debugger shows**: `for n in names` shows `n` (it was `for_var`); a list literal or list parameter reads as `[1, 2, 3]` instead of a pointer and `xs_len`, and a list parameter no longer shows twice; objects read as `Point {x = 3, y = 4}`; LLDB shows lists as their elements.

## Editors

- **VS Code**: Run / Debug buttons in the editor title of `.iron` files, and Run Test / Debug Test above every `test "..."` block.
- **Zed**: run buttons in the gutter on `func main` and on every test block, with Debug in the same menu (a debug locator turns the run task into a debug session).
- **Neovim**: `:IronRun`, `:IronTest [name]`, `:IronTestFile`, `:IronDebug`, `:IronDebugTest [name]`, and an nvim-dap configuration for the test under the cursor.
