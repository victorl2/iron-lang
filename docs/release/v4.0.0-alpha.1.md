# Iron v4.0.0-alpha.1 — Memory Model Overhaul

> Tagged from `main` at SHA `<FILL: short-sha post-tag>`. Acceptance corpus pass-rate at milestone close: see [Acceptance corpus pass-rate](#acceptance-corpus-pass-rate) below (measured on silvaserver, `iron-lsp-build:latest` 8 GB podman). Full reproducer in `docs/dev/PHASE-36-CLOSEOUT.md`.

Iron v4 is a ground-up rework of the language's memory model. The compiler now distinguishes binding tiers (`val` / `var`), parameter modifiers, reference-counted lifetimes (`rc` / `weak rc`), arena allocation, checked pointer types (`*T` / `*var T`), and resource discipline (`drop` / `copy` / `nocopy`) at the type level. The LSP, the three editor extensions, and the stdlib have been adapted to the new surface. This is an **alpha** release; the surface may change before GA.

## What's new

The §12 memory-model overhaul shipped in 17 sequential phases (17–33), followed by LSP adaptation (34) and grammar + editor + corpus catch-up (35). Each entry below is one sentence describing the feature; design closeout docs under `docs/dev/` carry the full story.

### Binding discipline (Phases 17–18)

- **val/var tier discipline (Phase 17)** — `val` is the default immutable binding; `var` opts into mutation at the binding site. Fields, locals, and parameters all participate.
- **Parameter modifiers (Phase 18)** — function and method parameters carry an explicit mutation tier; a `var` parameter signals the caller that the binding will be re-bound or the underlying memory mutated.

### Pointers and policies (Phases 19–21, 25–28)

- **Generational pointers (Phase 19)** — every heap allocation carries a generation counter; use-after-free is caught at every dereference. Foundation for everything below.
- **Checked pointer types `*T` / `*var T` (Phase 20)** — pointer mutability is part of the type. `*T` is a read-only checked pointer; `*var T` permits writes through the pointer.
- **`heap` policy + `free` (Phase 21)** — explicit `heap` allocation policy returns a fat pointer; the matched `free` releases it and invalidates outstanding pointers (caught at next dereference via the Phase 19 generation guard).
- **`*unchecked T` + `Box[T]` (Phase 25)** — escape hatch for FFI and zero-overhead interop. `*unchecked T` skips the generation check; `Box[T]` is a checked single-owner heap box.
- **`rc` policy (Phase 26)** — reference-counted shared ownership. Atomic refcount with a 24 B header (`refcount` + `drop_fn` + `weak_count`).
- **`weak rc` policy (Phase 27)** — non-owning observer of an `rc T`; `upgrade()` returns `T?` and is race-free against concurrent drops (Rust `Arc::Weak` discipline).
- **Arena allocation (Phase 28)** — explicit arena-scoped allocations release at arena exit; `rc` and `weak rc` are excluded from arenas (incompatible lifetime models).

### Purity and resources (Phases 22, 24)

- **`readonly` purity tightening (Phase 22)** — `readonly` methods structurally prevent mutation, including through transitively-readonly captures. `pure` is a strict subset of `readonly`.
- **Resource types `drop` / `copy` / `nocopy` (Phase 24)** — object declarations opt into resource discipline. `drop` blocks run at scope exit; `copy` declares deep-copy semantics; `nocopy` forbids implicit duplication.

### Storage shapes (Phase 23)

- **Bounded vector `[T; <=N]` (Phase 23)** — fixed-capacity stack-allocated vector; bounds checked at push.

### Optimizations (Phases 29–30)

- **Atomic refcount elision (Phase 29)** — local non-escaping `rc` allocations bypass atomic increments; verified via Phase 29 microbench.
- **Pointer-check elision (Phase 30)** — 4-tier escape analysis removes redundant generation checks when the compiler can prove no `free` is reachable between checks.

### Diagnostics and tools (Phases 31–32)

- **Debug allocator + leak detection (Phase 31)** — `ironc --debug-allocator` instruments every allocation with origin + leak-at-exit reporting.
- **`defer` statement (Phase 32)** — LIFO scope-exit hook. Pairs naturally with `heap` / `free` and resource types.

### Stdlib and ecosystem (Phases 33–35)

- **Stdlib container rewrite (Phase 33)** — new container surface: `Mutex[T]`, `RWLock[T]`, `Channel[T]` (bounded), `FileHandle` — all `nocopy` types with `drop`-on-scope-exit semantics. Resolved OQ-01 + OQ-06 (closure-capture vs container-drop ordering).
- **LSP adaptation (Phase 34)** — hover annotates the memory-model regime + readonly/pure status; completion gates v4-only keywords by context; 5 quickfixes for the new 800-range error codes (add `val`, insert `defer free`, drop `var` modifier, use `weak rc`, remove `readonly` + extract mutating block). HARD-24 parity gate stayed green throughout.
- **Grammar + editor extensions + corpus migration (Phase 35)** — tree-sitter and TextMate grammars cover every v4 construct; the three editor extensions (VSCode, Neovim, Zed) all pin `compatible_ironls = ">= 4.0.0, < 5.0.0"`; 225 of 388 v3-archive fixtures hand-migrated to `tests/integration/v4/migrated-from-v3/`, the remaining 163 documented as internal-IR / optimizer-internal / removed.

## Migration

The v3 → v4 syntax delta is mechanical for most user code but structural for code that relies on implicit mutation or unbounded references. The [migration guide](../site/migration-v3-to-v4.md) walks through every change with before/after code blocks.

There is **no automatic codemod** for this milestone (deliberate roadmap decision). Hand-migration with the LSP's 5 new quickfixes is the supported path.

## Known limitations / residuals

These items are deliberately deferred or are pre-existing environmental issues. They do not block v4.0.0-alpha.1.

Carried forward from Phase 34 closeout:

- TSan-instrumented runtime tests skip in CI (`libtsan` unavailable in the build container — CI infra issue, not a runtime defect).
- `v4_4.13-defer` WILL_FAIL polarity inversion (the build container picked up clang mid-phase, inverting the expected-fail polarity for one fixture).
- Four missing `.expected` files in `tests/integration/v4-fail/7.5-stdlib/` (carried from Plan 33-01).
- `test_typecheck` Phase 22 readonly-interface gap (documented in Phase 22 closeout).
- `test_parser_recursion_guard` stack-ulimit dependency.
- `benchmark_smoke` timeout on slower CI runners.
- `readonly-method-return-Result` fixture violations (documented residual in Phase 34 closeout).

Compiler / LSP residuals from Phase 34 closeout:

- Additional 800-range diagnostic code allocations are pending (`memory_model_hint` consolidation).
- LSP-10 "Extract mutating block" quickfix ships as a placeholder; full implementation deferred.

Alpha-stage caveats:

- The surface may change before GA. Pin your editor extension to `>= 4.0.0, < 5.0.0` (the default range in all three extensions) but expect minor surface refinements in beta and RC.
- The 168 requirements are CLOSED on the project tracker; that does not mean every edge case across them is exhaustively tested. The alpha period is when external users surface the remaining edge cases.
