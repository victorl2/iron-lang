# Iron v4.8.0-alpha: Test Blocks, Program Arguments and Loop Control

Tests live next to the code as `test "name" { ... }` blocks and run in parallel, isolated processes; `main` can take the command-line arguments and `OS.env` reads the environment; loops gain `break` and `continue`. The fuzz targets run again, and what they found is fixed: four parser hangs, two compiler crashes and most of the memory the language server kept per edit. This is an **alpha** release; the surface may change before GA.

## Test blocks

```iron
func add(a: Int, b: Int) -> Int { return a + b }

test "add works" {
    assert_eq(add(2, 3), 5)
}
```

- `test "name" { ... }` is a top-level declaration (`test` stays an ordinary name everywhere else). Every build type-checks test blocks; only the test build keeps them.
- `assert_eq(actual, expected)` and `assert_ne(a, b)` report the source line and both values: `assert_eq at math.iron:16: expected 5, got 4`.
- `ironc test file.iron [filter]` runs each selected test in its own process, several at a time. A panic or a failed assert fails that test only, and its output is shown under `FAILED`. The summary is `N passed, M failed[, K filtered out]`, and the exit status is 1 on any failure.
- `iron test [filter]` in a project compiles `vendor/`, `src/` and the test blocks in `tests/` into one test build, so a test in `src/` can reach its file's private functions and a test in `tests/` the project's `pub` API. `tests/test_*.iron` programs with their own `main` still run as before.

## Program arguments and the environment

- `func main(args: [String])` receives the command-line arguments (without the program name); `func main()` is unchanged. Any other signature is E0202.
- `import os` gives `OS.env(name) -> String?`, `OS.env_or(name, fallback)` and `OS.has_env(name)`. On Windows arguments and variables are read as UTF-16 and converted, so non-ASCII values arrive intact.
- A source file may start with a UTF-8 byte order mark.

## `break` and `continue`

- `break` leaves the innermost `while` or `for`; `continue` goes to its next iteration (for a range `for`, after the increment). Deferred statements and destructors of the scopes being left run first.
- Both are E0335 outside a loop, in a lambda, `defer` or `spawn` body inside one, and in a `parallel` loop.
- `return` inside a `defer` body is now E0336 (it crashed the compiler before); a lambda inside a defer body still returns from itself. A `defer` inside a deferred body runs when that body ends.

## Fixes found by fuzzing

The nightly fuzz job had not compiled for days; it builds again, its generator is compiled in every build so a new keyword cannot break it silently, and the job now fails on a crash, rotates its seed and keeps its corpus between nights. `docs/dev/fuzzing.md` describes the process.

- Parser hangs that ran the compiler (and the language server) out of memory: a statement keyword in an interface or patch body (`interface A { val x = 1 }`), a function type with a parameter that is not a type (`val d: func(1`), and a match arm past the nesting limit.
- A nested `defer` read freed memory while being lowered.
- Memory: each analysis left the scopes' symbol maps, the interface registry, the declaration list and the tokens of interpolated strings on the heap, about 11 KB per edit in the language server. The arena now frees them (`iron_arena_on_free`, `iron_arena_own_arr`); 88% of it is gone.

## Compiler and runtime fixes

- Runtime panics name the Iron source line (`site: main.iron:23`).
- Generic enum values take open type arguments from the expected type; `==` on enums with payloads compares the variant and the payload.
- `parallel for` over a list iterates its elements; a loop over strings or objects nested in another loop compiles; an empty list argument to a method takes the parameter type; interface methods can return enums and objects; a user type named `T` no longer breaks every build.
- Fused list chains on a temporary list (`xs.map(f).len()`, `xs.copy().len()`) read it after it was freed, and leaked.
- On Windows, two compiles running at the same time could write the same temporary C file.
- `iron fmt` formats by layout and keeps every token and comment.
- `install.ps1`: Windows programs no longer need the Build Tools.
