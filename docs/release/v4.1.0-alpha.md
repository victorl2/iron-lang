# Iron v4.1.0-alpha: Networking and Vendoring

Iron v4.1 adds a production-oriented networking stack to the standard library, hardens the v4 memory model, and removes the package manager in favor of vendoring third-party code. This is an **alpha** release; the surface may change before GA.

## Breaking change: no package manager

Iron no longer resolves, downloads, or locks dependencies. The `[dependencies]` table (GitHub and local-path entries), `iron.lock`, the `~/.iron/cache/` download cache, and GitHub tag resolution are gone. The standard library covers the common ground; anything else is copied into your project, the way Odin projects do it.

- Put third-party Iron source in `vendor/` next to `iron.toml`. `iron build`, `iron run`, and `iron check` compile every `.iron` file under `vendor/` together with `src/`.
- A vendored directory with its own `iron.toml` and `src/` contributes only `src/`, so a library made with `iron init --lib` can be copied in unchanged. `tests/`, `examples/`, `target/`, and hidden directories are skipped.
- `iron check` now checks the same sources `iron build` compiles, so multi-file projects resolve cross-file names.
- `iron init` no longer writes a `[dependencies]` table, and `ironls` no longer watches `iron.lock`.

**Migrating:** copy each dependency's source into `vendor/<name>/`, then delete the `[dependencies]` table and `iron.lock`. A manifest that still declares a dependency fails with a hint pointing at `vendor/`; an empty table or `raylib = true` only prints a warning (`import raylib` enables raylib). See the [project guide](https://ironlang.dev/guide/#vendoring).

## Networking

- **HTTP and HTTPS:** HTTP/1.1 clients and servers with REST methods, custom headers, chunked bodies, and HTML, JSON, text, and file responses. Verified HTTPS uses system trust roots or a custom CA; insecure modes are explicit development APIs.
- **Connection reuse:** a bounded, same-origin `HttpClient` pool with idle eviction, per-operation deadlines, and a single safe retry for bodyless `GET`/`HEAD` only.
- **Staged HTTPS admission:** `HttpsServer.accept_tcp` returns a pending connection so each TLS handshake can run in its own handler with its own deadline.
- **WebSocket:** RFC 6455 WS and WSS clients plus HTTP and HTTPS server upgrades, with ordered subprotocol negotiation.
- **Binary-safe I/O:** TCP, UDP, and file APIs handle arbitrary bytes. Every networking and file result model has an explicit release helper, and the models run clean under LeakSanitizer.
- **Atomic no-overwrite moves:** `IO.move_file(src, dst, false)` can no longer replace a destination created concurrently by another task or process.

See the [networking guide](https://ironlang.dev/networking/).

## Language and compiler

- **Mutating method calls write through references:** calling a mutating method on a `var` parameter, a lambda-captured `var`, an rc or heap binding, or a field reached through `self` now mutates the original object instead of a temporary copy.
- **Interface `var` bindings mutate in place:** mutating interface methods dispatch through the binding's storage, and `var <Interface>` parameters follow the copy-in / write-back contract of other `var` parameters. Interface-typed fields and passing a concrete object to an interface parameter now compile correctly.
- **Interface default bodies:** an interface method with a body is inherited by implementors that do not define it.
- **Per-site unchecked indexing:** `xs.get_unchecked(i)` and `xs.set_unchecked(i, v)` skip the bounds check at exactly that site (`--debug-build` keeps a guard), recovering C parity in hot loops.
- **v4 remediation:** the acceptance suite runs fully green at phase gate 37. New runtime panics for division by zero and index out of bounds, guarded integer division, module-level globals, leak-free reference counting, and several unsound optimizer elisions removed.
- **C backend optimizations:** conservative scalar copy coalescing, proven local integer storage narrowing, and structured-loop emission, with range-analysis leak fixes.

## Documentation

- Iron is presented as a general-purpose native language, with four new runnable non-game examples and a documentation CI gate.
- The website's Package Manager page is now the [Project Guide](https://ironlang.dev/guide/), including vendoring and migration steps.

## Known limitations

- Vendored code shares the project's namespace: `import name` is accepted, but aliased access (`import name as n`) does not work for vendored or project-local modules yet.
- Vendoring C libraries is not supported yet: user `extern func` declarations get no C prototype, and snake_case names map to PascalCase C symbols.
