# Iron v4.9.0-alpha: Editor Support and Source-Level Debugging

VS Code understands Iron programs the way the compiler does: no false errors, hover, go to definition, completion, signature help, rename and references inside function bodies and into the standard library, semantic highlighting and inlay hints. `iron debug` and `iron build --debug` debug a program at the Iron level, with breakpoints and stepping on `.iron` lines, locals under their Iron names and values shown as Iron values, in gdb, LLDB, the Visual Studio debugger and VS Code. Error messages propose a fix. This is an **alpha** release; the surface may change before GA.

## Editor

The language server analyzed each buffer without the standard library, so valid programs showed errors for `Map`, `Set`, String and list methods and every imported module. It now analyzes a buffer exactly as `ironc check` does; all 537 v4 programs show no error in the editor.

- **Hover and go to definition inside function bodies:** calls, methods, fields, enum variants, parameters and types, for the file's own declarations and the standard library's (go to definition opens `string.iron` at `upper`). Builtins without a declaration (`Map.put`) show their receiver and result type.
- **Completion after `.`** lists the receiver's members whatever the receiver is: a local or parameter of any type, a field chain, a call result, a literal, or a type name for statics and variants (`Math.sqrt`, `Color.Red`). List, `Map` and `Set` builtins are included.
- **Signature help** on method calls (`s.replace(`, `Math.pow(`, user methods).
- **Semantic highlighting:** types, functions, methods, parameters, fields, enum members, readonly bindings and standard library names are colored as what they are.
- **Inlay hints:** the inferred type after a `val` / `var` written without one, and parameter names before arguments (`area(w: 2, h: 3)`).
- **Rename, references and highlight** work from a declaration's name and edit only names. Renaming a function used to replace its whole declaration.
- Diagnostics follow edits after 150 ms (was 250 ms). The server's memory stays flat when many files are open.
- Windows: go to definition into the standard library opens the file, and a standard library file opened in the editor reports no errors.

## Debugging

- `iron build --debug` / `ironc build --debug` (and `run`) compile with debug information that points at the `.iron` source, without optimization or inlining, so breakpoints, stepping and the call stack follow Iron lines and functions. Windows builds get a PDB.
- Locals and parameters carry their Iron names in the debugger (compiler temporaries still appear as `_vN`).
- `lib/debug/` holds formatters for gdb (`iron_gdb.py`) and LLDB (`iron_lldb.py`). They show a `String` as its text, lists and sets as their elements, maps as their entries and `T?` as its value or `null`. On Windows the views are linked into the PDB, so the Visual Studio debugger and VS Code show them without configuration.
- `iron debug` (in a package, or `iron debug main.iron`) builds with `--debug` and starts LLDB (macOS) or gdb with the formatters loaded; arguments after `--` go to the program.
- A panic stops the debugger with the failing Iron line on the call stack.
- The VS Code extension accepts breakpoints in `.iron` files; the guide's Debugging section has launch configurations for gdb, LLDB and the Visual Studio debugger.

## Diagnostics

Errors propose a fix:
- the closest name for an undefined identifier, method or enum variant ("did you mean 'upper'?");
- the declared signature on a wrong argument count;
- how to convert on a type mismatch;
- the literal a wrong literal should be;
- `var` instead of `val` when a binding is mutated;
- notes at the first declaration of a duplicate type and at an unclosed `{`.

Expected-token errors name what was found and what was expected. `"{x y}"` no longer compiles while dropping `y`.

## Language and runtime

- `[T?]`, `Map[K, V?]` and `Channel[T?]`: collections of nullable elements, with `null` literals, narrowing in `for` loops, and map values that are present but `null`.
- Lists of maps, sets and channels compile.
- Int literals out of range are E0292; `-9223372036854775808` is the smallest Int.
- Shifts are defined for every count (a negative count panics with the source line). Bitwise operators accept every integer width.
- `to_int` / `to_float` return 0 for text that is not entirely a number. `rindex_of("")` returns the length.
- An unknown enum variant no longer crashes the compiler or the language server after reporting E0228.
- An analysis frees all of its memory when it is done (it left 406 KB behind over the v4 programs), so the language server no longer grows with each edit.

## Install

The installers now verify the archive's SHA-256 before extracting.

```sh
curl --proto '=https' --tlsv1.2 -sSfL https://ironlang.dev/install.sh | sh -s -- --version v4.9.0-alpha
```

```powershell
irm https://ironlang.dev/install.ps1 | iex
```
