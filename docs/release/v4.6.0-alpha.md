# Iron v4.6.0-alpha: Maps, Sets and One Way to Construct

`Map[K, V]` and `Set[T]` are real hash containers, every standard library container is constructed the same way, and the website is generated from the reference manual. This is an **alpha** release; the surface may change before GA.

## Maps and sets

- **`Map[K, V]` and `Set[T]`** are open-addressing hash tables constructed empty with their type arguments written out: `var m = Map[String, Int]()`, `var s = Set[Int]()`. Maps have `put`, `get` (a missing key is a panic), `get_or`, `has`, `remove`, `len`, `clear`, `keys`, `values`, `copy` and `take`; sets have `add`, `has`, `remove`, `len`, `clear`, `values`, `copy` and `take`. `for (key, value) in m` and `for item in s` iterate them.
- **Keys** are the integer types, `Bool`, `String`, and objects that implement `Hashable` (`hash()` and `equals()`). **Values** are anything a list can hold: strings, objects, lists, `rc` handles, enums, other maps.
- **Ownership** follows lists: the table owns its keys and values, `put` and `add` take their arguments (a value copied out of a binding is retained or cloned first), `get` and `get_or` hand out owned copies, `remove`, `clear` and scope exit drop entries, a map binding is never duplicated implicitly (E0328; use `copy()`, `take()` or `rc Map[K, V]`), and mutators need a `var` binding (E0235).
- Every lifecycle path is checked by a new leak oracle (`leaks` on macOS, valgrind on Linux) over 27 fixtures, plus 17 runtime unit tests covering growth, collisions, tombstone churn, string refcounts, clone and take.

## Constructors

- Every runtime-backed container is constructed like any object: `Channel[Int](4)`, `Mutex(v)` or `Mutex[T](v)`, `RWLock(v)`, `Box(v)` or `Box[T](v)`, `Arena(bytes)`, `Arena.threadsafe(bytes)`. The old `Channel.new`, `Mutex.new`, `RWLock.new`, `Box.new`, `Arena.new`, `Arena.with_capacity` and `Arena.new_threadsafe` spellings are rejected with **E0333** and a hint. `Box.null()` and `FileHandle.open(path)` stay, as named factories.
- Several type arguments parse in a generic construct or call: `Pair[Int, String](1, "x")`.

## Website and documentation

- `ironlang.dev/docs/` is generated from `docs/language_definition.md` at deploy time, so the site can no longer describe features that do not exist (the old page still documented `extends`, thread pools, auto-free and `draw` blocks). The manual is also published as `/llms/reference.md`, listed first in `llms.txt` and included in `llms-full.txt`.
- The manual documents maps and sets (section 9.10) with a compiler-verified example; a runnable `docs/examples/native_collections.iron` is featured on the landing page; the historical implementation plan is removed.

## Fixes

- A test-runner race reported a correctly printed panic as missing (`set -o pipefail` with `echo | grep -q`), the cause of the intermittent `boundary_debug_allocator_uaf` failure (#228).
- The drop thunk of a boxed `rc` capture had an invalid C name.
- Object-element list typedefs are emitted on demand, so a list type that appears only as a method result compiles.
- The macOS signing job falls back to unsigned `ironls` archives with checksums when the Apple secrets are absent, so every release publishes all its assets.
